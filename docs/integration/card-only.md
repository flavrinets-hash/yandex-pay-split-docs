# Схема интеграции: оплата картой

Пошаговая схема подключения для внешнего партнёра, который хочет подключить в своём интернет-магазине только оплату картой, с бейджами и виджетом в карточке товара и на способе оплаты и с возможностью проводить возвраты.

## Подготовка к интеграции

Перед началом работы мерчанту необходимо зарегистрировать магазин в **Личном кабинете Яндекс Пэй**, получить API-ключ для авторизации запросов и указать [Callback URL](https://pay.yandex.ru/docs/ru/custom/backend/merchant-api/webhook#shag-1-ustanovite-callback-url) (эндпоинт на бэкенде магазина для приёма асинхронных вебхуков со статусами платежей и возвратов).

!!! warning "Обратите внимание"
    Callback URL указывается без эндпоинта **/v1/webhook**.

## Пошаговый процесс подключения

### Шаг 1. Подключение библиотеки на фронтенде

Разработчик добавляет скрипт Web SDK Яндекс Пэй на страницы интернет-магазина:

```html
<script src="https://pay.yandex.ru/sdk/v1/pay.js" onload="onYaPayLoad()" async></script>
```

### Шаг 2. Размещение бейджей и виджетов в интерфейсе

Для информирования покупателей в HTML-код страниц добавляются DOM-контейнеры:

- Рядом с ценой каждого товара монтируются умные [бейджи](https://pay.yandex.ru/docs/ru/custom/web-sdk/badges).
- Под кнопкой покупки монтируется [виджет](https://pay.yandex.ru/docs/ru/custom/web-sdk/ultimate-widget).
- Отрисовывается вариант «Банковская карта».

!!! important "Важно"
    При инициализации элементов Web SDK необходимо передавать параметр **availablePaymentMethods: ["CARD"]**. [Это отключает отображение информации о рассрочке/Сплите.](https://pay.yandex.ru/docs/ru/custom/web-sdk/buttons#chto-takoe-knopka-oplaty)

### Шаг 3. Инициализация оплаты (Frontend → Backend)

Покупатель выбирает «Яндекс Пэй», нажимает «Оплатить», фронтенд передаёт запрос на бэкенд своего магазина с составом корзины и суммой.

### Шаг 4. Создание заказа через API (Backend → Яндекс Пэй)

Бэкенд магазина отправляет авторизованный HTTP-запрос к Яндекс Пэй для создания платёжной сессии:

- **Метод:** [`POST https://pay.yandex.ru/api/merchant/v1/orders`](https://pay.yandex.ru/docs/ru/custom/backend/yandex-pay-api/order/merchant_v1_orders-post#request)
- **Заголовки:** `Authorization: Api-Key <API-ключ мерчанта>`
- **Тело запроса:** передаются данные корзины, итоговая сумма и параметр **availablePaymentMethods: ["CARD"]** для ограничения способов оплаты.
- **Результат:** Яндекс Пэй возвращает ссылку на платёжную форму в поле [paymentUrl](https://pay.yandex.ru/docs/ru/custom/backend/yandex-pay-api/order/merchant_v1_orders-post#body1) внутри объекта `data`.

### Шаг 5. Перенаправление и проведение платежа (Frontend → Яндекс Пэй)

1. Бэкенд возвращает полученный `paymentUrl` на фронтенд.
2. Фронтенд перенаправляет покупателя на защищённую форму оплаты Яндекса для ввода данных карты.

### Шаг 6. Подтверждение оплаты через вебхук (Яндекс Пэй → Backend)

После успешного списания средств Яндекс Пэй отправляет асинхронный POST-запрос на Callback URL магазина.

- Передаётся JWT-токен со событием **ORDER_STATUS_UPDATED** и статусом заказа [order.paymentStatus: "CAPTURED"](https://pay.yandex.ru/docs/ru/custom/backend/merchant-api/webhook#webhook-examples).
- Сервер магазина верифицирует цифровую подпись JWT-токена с помощью публичных ключей Яндекса (JWK), проверяет совпадение `merchantId` и обновляет статус заказа на «Оплачен».
- **Ответ бэкенда Яндексу:**
    - **При успехе:** [возвращает 200 OK](https://pay.yandex.ru/docs/ru/custom/backend/merchant-api/webhook#200-ok) с телом **{"status": "success"}**.
    - **При ошибке:** [возвращает 400 Bad Request](https://pay.yandex.ru/docs/ru/custom/backend/merchant-api/webhook#400-bad-request) с кодом ошибки. Если Яндекс не получает статус 200 OK, нотификация будет повторно отправляться в течение 24 часов.

### Шаг 7. Проведение возвратов (Backend → Яндекс Пэй)

Если покупатель отменяет покупку полностью или частично, бэкенд магазина инициирует асинхронный процесс возврата средств.

- **Эндпоинт:** `POST https://pay.yandex.ru/api/merchant/v2/orders/{order_id}/refund`
- **Заголовки:** `Authorization: Api-Key <API-ключ мерчанта>`
- **[Параметры тела запроса (Body)](https://pay.yandex.ru/docs/ru/custom/backend/yandex-pay-api/order/merchant_v2_refund-post#body):**
    - **externalOperationId:** уникальный ID операции на стороне магазина, выполняющий роль токена идемпотентности (защищает от дублирования возвратов при сетевых сбоях).
    - **refundAmount:** сумма возврата (минимум 1 рубль). Для полного возврата достаточно передать только его.
    - **refundCart (при частичном возврате):** содержит список конкретных позиций (`productId`, `quantityCount`, `price`) для возврата. При полном возврате передавать не требуется. *При использовании refundCart документация рекомендует передавать externalOperationId, чтобы не было повторного возврата за позиции.*
    - *Альтернативный способ.* **targetCart:** передаётся целевое состояние корзины — остаток товара у покупателя после возврата. Передавать `refundCart` и `targetCart` одновременно нельзя.
- **Результат исполнения:**
    - **Синхронный ответ:** [возвращает 200 OK](https://pay.yandex.ru/docs/ru/custom/backend/yandex-pay-api/order/merchant_v2_refund-post#body1) со статусом операции `PENDING`.
    - **Асинхронные вебхуки:** после обработки банком отправляются два нотификационных запроса на Callback URL:
        - **OPERATION_STATUS_UPDATED:** со статусом операции `SUCCESS`;
        - **ORDER_STATUS_UPDATED:** со статусом заказа `PARTIALLY_REFUNDED` (если остались позиции) или `REFUNDED` (при полном возврате).
